Prologue

The Paradigm Shift: From Scripts to Agents

To build effectively with LangChain, it helps to pause and look at how our industry evolved. We didn't jump straight from basic Python scripts to autonomous multi-agent pipelines overnight:

💡 The Mental Model: The Four Eras of Software
Era 1 (Rule-Based): Explicit if/else statements. Reliable, but crashes the moment an unexpected input arrives.
Era 2 (Statistical ML): Classifiers and regression models that interpolate patterns. Great at predicting numbers, but unable to speak or reason.
Era 3 (Generative LLMs): Massive autoregressive models reciting the collective knowledge of humanity with astonishing fluency—yet passive, with no hands to interact with databases or APIs.
Era 4 (Agentic Systems): Giving that reasoning model tools, persistent state, reflection loops, and verifiable boundaries.

Dimension Procedural Code Classical ML Generative LLM Agentic Systems
Primary Unit Boolean functions & loops Weights & tree splits Attention heads & tokens State graphs & tool actions
External Interaction Hardcoded API calls Passive score emission Passive text generation Autonomous dynamic tool dispatch

⚠️ A Trap to Avoid: The Monolithic Prompt
When building your first AI app, the temptation is always to write a 4,000-word prompt instructing the model how to handle every single edge case. In practice, attention degrades as context expands (the Lost in the Middle phenomenon). The professional pattern is decomposing tasks into focused, modular runnables connected through structured pipelines.

Module 1

Foundations: Model Mechanics & LCEL (LangChain Expression Language)

At its core, an autoregressive language model computes probabilities for what token should come next. When you pass a string to an LLM, it projects logits across a vocabulary $V$ and scales them via the Softmax function:

Formula 1 P(w_i) = exp(z_i / T) / Σ exp(z_j / T)
Walkthrough: How Temperature (T) Mathematically Changes Output Logits
Suppose the model has raw logits $z = [4.0, 2.0, 1.0, 0.5]$ for candidate tokens.

• At T = 1.0 (Standard): Logits remain unchanged. Probabilities are ~82% for token 1, 11% for token 2, 4% for token 3.
• At T = 0.2 (Greedy / Deterministic): Logits are divided by 0.2, becoming $[20, 10, 5, 2.5]$. When exponentiated, token 1 absorbs 99.99% of the probability mass. This is why $T=0.0$ is mandatory for deterministic JSON parsing, SQL generation, and factual RAG extraction.

Why LCEL Over Legacy LangChain?

In older versions of LangChain, workflows relied on classes like LLMChain and SequentialChain. They were difficult to debug and had clunky syntax. Modern LangChain introduces LCEL, which uses the Unix-style pipe operator (|) to compose components that all adhere to a unified Runnable interface (invoke, batch, stream).

💡 The Mental Model: Standardized Adapters
Think of LCEL like Lego blocks: every block has the same standard connectors. A PromptTemplate takes a dictionary and outputs a prompt. A ChatModel takes a prompt and outputs a message. An OutputParser takes a message and outputs a clean string. Because they all share the same interface, chaining them is as simple as prompt | model | parser.

Module 2

The 5 Pillars of Production RAG Architecture

Retrieval-Augmented Generation (RAG) solves three persistent limitations of standalone LLMs: Static Knowledge Cutoffs, Hallucinations, and Enterprise Data Blindspots. Rather than retraining multi-billion-parameter weights, RAG retrieves precise factual context dynamically at query time.

Every production RAG system is built upon 5 foundational pillars:

Pillars 1 & 2: Document Loading & Chunking Mathematics

Raw enterprise documents (PDFs, transcripts, markdown files) must be converted into manageable pieces. Splitting purely on character count or single newlines produces broken sentences and severed facts.

⚠️ Why Chunk Overlap is Mandatory
If you slice a document strictly every 1,000 characters with zero overlap, a key sentence spanning characters 980 to 1,020 gets severed in half. Neither chunk understands the complete thought! A 200-character overlap acts like a safety margin, ensuring boundary context is preserved.
Formula 4 Effective_Stride = Chunk_Size - Chunk_Overlap
rag_ingestion_chunking.py — Loading & Splitting
from langchain_community.document_loaders import PyPDFLoader, YoutubeLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter

# 1. Load Local PDF Document
pdf_loader = PyPDFLoader("data/sample_handbook.pdf")
pdf_docs = pdf_loader.load()
print(f"Loaded {len(pdf_docs)} pages from PDF.")

# 2. Configure Recursive Splitter with Natural Language Separator Hierarchy
# Separator hierarchy: Paragraphs -> Newlines -> Spaces -> Characters
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,        # Maximum characters per chunk
    chunk_overlap=200,      # Overlap preserves boundary context
    separators=["\n\n", "\n", " ", ""]
)

# 3. Perform Chunking
chunks = text_splitter.split_documents(pdf_docs)
print(f"Generated {len(chunks)} contextual chunks from {len(pdf_docs)} pages.")
print(f"Sample Chunk 0 Metadata: {chunks[0].metadata}")
print(f"Sample Chunk 0 Preview: {chunks[0].page_content[:200]}...")

Pillars 3, 4 & 5: High-Dimensional Vectors, Storage & Synthesis

Embeddings map text chunks into geometric coordinates. When a user asks a question, we compute its embedding and find the nearest document chunks using Cosine Similarity:

Formula 2 Cosine_Similarity(A, B) = (A · B) / (||A|| * ||B||)

from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough
from langchain_core.output_parsers import StrOutputParser

# 1. Create Vector Store with Embeddings
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    collection_name="enterprise_knowledge"
)

# 2. Expose as Standard Retriever (Top-3 nearest neighbors)
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

# 3. Document Formatter Helper Function
def format_docs(docs):
    return "\n\n---\n\n".join([doc.page_content for doc in docs])

# 4. Strict Grounding RAG Prompt Template
rag_prompt = ChatPromptTemplate.from_template("""
You are an expert enterprise research assistant.
Answer the question based STRICTLY and SOLELY on the provided context below.
If the answer cannot be deduced from the context, state: "I do not have sufficient information in the verified knowledge base."
Do not speculate or extrapolate.

CONTEXT:
{context}

QUESTION:
{question}

GROUNDED ANSWER:
""")

# 5. End-to-End LCEL Composition
# Flow: Takes {"question": str} -> Retrieves & formats docs -> Populates prompt -> Generates -> Parses
rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | rag_prompt
    | ChatOpenAI(model="gpt-4o", temperature=0.0)
    | StrOutputParser()
)

# 6. Execute Query
if __name__ == "__main__":
    query = "What is the penalty for late fee submission?"
    answer = rag_chain.invoke(query)
    print("=== RAG Response ===")
    print(answer)

Advanced RAG: Maximal Marginal Relevance (MMR)

Standard Top-K retrieval often returns five nearly identical paragraphs from different pages of a document. Maximal Marginal Relevance (MMR) balances query similarity with diversity among already-selected chunks:

Formula 3 MMR = argmax [ λ * Sim1(d_i, Q) - (1 - λ) * max Sim2(d_i, d_j) ]

Setting $\lambda = 0.5$ provides an ideal balance between topical relevance and diverse context.

Module 3

Giving LLMs Hands: Tools, Function Calling & ReAct Loops

An LLM that can only speak is limited. By binding external tools defined with Pydantic schemas, you allow the model to emit structured JSON requests that your application executes on its behalf.

⚠️ The #1 Reason Tools Fail: Vague Docstrings
The LLM cannot see your Python function's code; it only sees the function name, its arguments, and its docstring. If your docstring is "Performs calculation", the LLM will hallucinate arguments or refuse to invoke it. Write docstrings as if you are explaining the function to a new teammate on day one.

Production Source Code: Tool Definition & ReAct Loop

agent_tools_react.py — Tool Definition & Execution Loop
from langchain_core.tools import tool
from pydantic import BaseModel, Field
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage, ToolMessage

# 1. Define Strict Pydantic Schema
class StockPriceInput(BaseModel):
    ticker: str = Field(description="The 1-5 letter stock ticker symbol, e.g., AAPL, NVDA, TSLA")

@tool("get_stock_price", args_schema=StockPriceInput)
def get_stock_price(ticker: str) -> str:
    """Fetches real-time price and market stats for a given stock ticker."""
    mock_data = {"AAPL": "$224.50", "NVDA": "$128.20", "TSLA": "$245.10"}
    price = mock_data.get(ticker.upper(), "Ticker not found.")
    return f"Stock: {ticker.upper()} | Real-time Price: {price}"

# 2. Bind Tools to LLM
model = ChatOpenAI(model="gpt-4o", temperature=0.0)
tools = [get_stock_price]
tools_dict = {t.name: t for t in tools}
model_with_tools = model.bind_tools(tools)

# 3. Finite State Machine: The ReAct Execution Loop
messages = [
    SystemMessage(content="You are an expert financial analyst. Use available tools to look up real data."),
    HumanMessage(content="What is the current stock price of Apple and Nvidia?")
]

print("Starting Agent Loop...")
while True:
    response = model_with_tools.invoke(messages)
    messages.append(response)
    
    # If the model does not request any tool calls, it has reached its final answer!
    if not response.tool_calls:
        print("\n=== Final Agent Answer ===")
        print(response.content)
        break
        
    # Execute requested tools
    for tool_call in response.tool_calls:
        fn_name = tool_call["name"]
        fn_args = tool_call["args"]
        call_id = tool_call["id"]
        
        print(f"-> Agent invoked tool: {fn_name}({fn_args})")
        tool_result = tools_dict[fn_name].invoke(fn_args)
        
        # Append observation as ToolMessage
        messages.append(ToolMessage(content=str(tool_result), tool_call_id=call_id))

Multi-Agent Systems: Research Pipeline with Binary .pkl Caching

Complex research is too much for a single agent. In Project 1, we split the workflow across three specialized agent personas:
1. Search Scout: Queries the web and extracts high-authority sources.
2. Reader Analyst: Scrapes page contents and extracts key technical takeaways.

To prevent burning API quota during development, we back the pipeline with an automatic binary .pkl cache.

Complete 4-File Project Implementation

project1_multi_agent/cache_manager.py — Binary Persistence Layer
import os
import pickle
import hashlib
from typing import Any, Optional

CACHE_DIR = os.path.join(os.path.dirname(__file__), ".cache")
os.makedirs(CACHE_DIR, exist_ok=True)

def _generate_key(prefix: str, payload: str) -> str:
    hasher = hashlib.sha256()
    hasher.update(payload.encode("utf-8"))
    return f"{prefix}_{hasher.hexdigest()[:16]}.pkl"

def save_to_cache(prefix: str, payload: str, data: Any) -> str:
    """Serializes Python data structure directly to .pkl file."""
    filepath = os.path.join(CACHE_DIR, _generate_key(prefix, payload))
    with open(filepath, "wb") as f:
        pickle.dump(data, f, protocol=pickle.HIGHEST_PROTOCOL)
    return filepath

def load_from_cache(prefix: str, payload: str) -> Optional[Any]:
    """Deserializes data from .pkl if it exists; returns None on cache miss."""
    filepath = os.path.join(CACHE_DIR, _generate_key(prefix, payload))
    if os.path.exists(filepath):
        with open(filepath, "rb") as f:
            return pickle.load(f)
    return None

import os
import requests
from bs4 import BeautifulSoup
from langchain_core.tools import tool
from cache_manager import load_from_cache, save_to_cache

@tool("web_search")
def web_search(query: str) -> str:
    """Searches the web for relevant URLs based on a query."""
    cached = load_from_cache("search", query)
    if cached:
        return f"[FROM PKL CACHE]\n{cached}"
        
    simulated_results = (
        f"1. https://en.wikipedia.org/wiki/LangChain - LangChain Architecture Overview\n"
        f"2. https://arxiv.org/abs/2305.10601 - Multi-Agent System Methodologies\n"
        f"3. https://python.langchain.com - Official Documentation"
    )
    save_to_cache("search", query, simulated_results)
    return simulated_results

@tool("scrape_webpage")
def scrape_webpage(url: str) -> str:
    """Fetches raw text content from a verified URL."""
    cached = load_from_cache("url", url)
    if cached:
        return f"[FROM PKL CACHE]\n{cached}"
        
    try:
        resp = requests.get(url, timeout=5)
        soup = BeautifulSoup(resp.text, "html.parser")
        text = soup.get_text(separator=" ", strip=True)[:2500]
    except Exception as e:
        text = f"Simulated content extracted for {url}: LangGraph introduces cyclical graphs for agent loops."
        
    save_to_cache("url", url, text)
    return text

import os
import pickle
import hashlib
from typing import Any, Optional

CACHE_DIR = os.path.join(os.path.dirname(__file__), ".pkl_cache")
os.makedirs(CACHE_DIR, exist_ok=True)

def get_cache_path(video_id: str, artifact_type: str) -> str:
    safe_name = f"{video_id}_{artifact_type}.pkl"
    return os.path.join(CACHE_DIR, safe_name)

def dump_artifact(video_id: str, artifact_type: str, data: Any) -> str:
    path = get_cache_path(video_id, artifact_type)
    with open(path, "wb") as f:
        pickle.dump(data, f, protocol=pickle.HIGHEST_PROTOCOL)
    print(f"[CACHE EXPORT] Serialized {artifact_type} for {video_id} -> {path}")
    return path

def load_artifact(video_id: str, artifact_type: str) -> Optional[Any]:
    path = get_cache_path(video_id, artifact_type)
    if os.path.exists(path):
        with open(path, "rb") as f:
            data = pickle.load(f)
        print(f"[CACHE HIT] Loaded {artifact_type} for {video_id} directly from disk!")
        return data
    return None

project2_video_assistant/vector_store.py — Vector Indexing & Pickle Export
import numpy as np
from typing import List, Dict, Any, Tuple
from langchain_openai import OpenAIEmbeddings
from ingest import get_video_transcript
from cache_manager import load_artifact, dump_artifact

class VideoVectorIndex:
    def __init__(self, texts: List[str], embeddings_matrix: np.ndarray, metadata: List[Dict[str, Any]]):
        self.texts = texts
        self.matrix = embeddings_matrix  # Shape: (N, D)
        self.metadata = metadata

    def search(self, query_vector: np.ndarray, k: int = 2) -> List[Tuple[Dict[str, Any], float]]:
        norm_matrix = np.linalg.norm(self.matrix, axis=1)
        norm_q = np.linalg.norm(query_vector)
        dot_products = np.dot(self.matrix, query_vector)
        similarities = dot_products / (norm_matrix * norm_q + 1e-9)
        
        top_indices = np.argsort(similarities)[::-1][:k]
        return [(self.metadata[i], float(similarities[i])) for i in top_indices]

def get_or_build_video_index(video_id: str) -> VideoVectorIndex:
    cached_index = load_artifact(video_id, "vector_index")
    if cached_index:
        return cached_index

    transcript = get_video_transcript(video_id)
    texts = [item["text"] for item in transcript]
    
    print("[EMBEDDINGS] Computing vector embeddings via OpenAI...")
    emb_client = OpenAIEmbeddings(model="text-embedding-3-small")
    vectors = emb_client.embed_documents(texts)
    matrix = np.array(vectors)

    index = VideoVectorIndex(texts, matrix, transcript)
    dump_artifact(video_id, "vector_index", index)
    return index
project2_video_assistant/tools.py — Timestamp Tools
from langchain_core.tools import tool
from langchain_openai import OpenAIEmbeddings
import numpy as np
from vector_store import get_or_build_video_index

CURRENT_VIDEO_ID = "dQw4w9WgXcQ"

def format_timestamp(seconds: float) -> str:
    m = int(seconds // 60)
    s = int(seconds % 60)
    return f"{m:02d}:{s:02d}"

@tool("find_video_timestamp")
def find_video_timestamp(query: str) -> str:
    """Finds the exact minute:second timestamp where a concept is discussed in the video."""
    index = get_or_build_video_index(CURRENT_VIDEO_ID)
    emb_client = OpenAIEmbeddings(model="text-embedding-3-small")
    query_vec = np.array(emb_client.embed_query(query))
    
    results = index.search(query_vec, k=2)
    output = []
    for meta, score in results:
        ts = format_timestamp(meta["start"])
        output.append(f"[{ts}] (Score: {score:.3f}): \"{meta['text']}\"")
    return "\n".join(output)

Placement Interview Questions — Agentic AI & LangChain/LangGraph

Curated from real FAANG, product company & service interviews. Click any answer to expand.

Q1. What is LangChain? What problem does it solve?
Show Answer
LangChain chains LLM calls with tools, memory, and data sources. It solves: 1) LLMs are stateless (adds memory). 2) LLMs cannot act (adds tool calling). 3) Context window limits (adds RAG). 4) Complex multi-step tasks (adds chains and agents).
Q2. Explain RAG (Retrieval Augmented Generation) architecture.
Show Answer
RAG: 1) Indexing: Chunk docs → embed → store in vector DB. 2) Retrieval: Query embedded → cosine similarity search → top-K chunks. 3) Augmentation: Chunks injected into LLM prompt. 4) Generation: LLM generates grounded response. Prevents hallucination.
Q3. What is the ReAct pattern in agents?
Show Answer
ReAct (Reason + Act): Agent interleaves reasoning with tool actions. Loop: Thought → Action → Observation → Thought → ... → Final Answer. Enables multi-step planning. Implemented in LangChain via AgentExecutor.
Q4. What is LangGraph? How does it differ from LangChain?
Show Answer
LangGraph is a stateful multi-agent orchestration framework. It models workflows as directed graphs (nodes=functions, edges=transitions). Unlike linear chains, it supports: cycles/loops, conditional branching, parallel branches, shared typed state, and human-in-the-loop interrupts.
Q5. Explain the difference between zero-shot, few-shot, and chain-of-thought prompting.
Show Answer
Zero-shot: Task description only. Few-shot: 2–5 input→output examples in prompt. CoT: 'Let's think step by step' → forces reasoning trace → dramatic accuracy improvement. Self-Consistency: Sample multiple CoT paths, take majority vote.
Q6. What is function/tool calling in LLMs?
Show Answer
Tool calling lets LLMs output structured JSON specifying a function name and arguments. The host executes the function and returns results. Enables: web search, database queries, code execution, API calls. Implemented via OpenAI tool_choice, Gemini function declarations, or LangChain @tool.
Q7. Explain vector embeddings and similarity search.
Show Answer
Embeddings map text to dense vectors where semantic similarity ≈ geometric proximity. Models: text-embedding-3, sentence-transformers. Similarity: cosine = (A·B)/(|A||B|). ANN search (HNSW, IVF) in Faiss/Pinecone enables sub-linear query time at scale.
Q8. What is a prompt template and why is it important?
Show Answer
Prompt templates parameterize LLM inputs, separating instructions from dynamic data. Benefits: reusability, testability, injection safety, version control. LangChain's PromptTemplate/ChatPromptTemplate supports f-string and jinja2 formatting.
Q9. What is the difference between an Agent and a Chain in LangChain?
Show Answer
Chain: Fixed, deterministic sequence of operations. No decision-making. Agent: LLM decides at runtime which tools to call and in what order. Use chains for predictable pipelines; agents for open-ended tasks requiring tool selection and iteration.
Q10. What are the key components of a LangGraph workflow?
Show Answer
StateGraph: Typed shared state (TypedDict). Nodes: Python functions that read/write state. Edges: Direct or conditional transitions. Checkpointer: Persists state for resumability. Subgraphs: Composable agent teams. Interrupt: Pause for human approval.
