Chapter 01 • Core Foundations

Foundations of Natural Language Processing

Linguistic intuitions, core challenges, and the architectural taxonomy of modern language systems.

Natural Language Processing (NLP) is the specialized branch of artificial intelligence, machine learning, and computational linguistics focused on giving computers the capability to understand, interpret, manipulate, and generate human language in a meaningful and contextual manner.

1. Why Natural Language Processing is Exceptionally Hard

Unlike structured tabular data (numbers, dates) or images (pixel intensity matrices with spatial continuity), human text is symbolic, discrete, ambiguous, and culturally contextual. The core linguistic challenges include:

  • Lexical Ambiguity (Polysemy & Homonymy): A single word can carry radically different meanings based entirely on context. Consider: "He deposited cash into the bank" vs. "The river bank was overflowing".
  • Syntactic & Structural Ambiguity: Phrases can yield multiple parse trees. Example: "I saw the man with a telescope" (Did I use a telescope, or did the man have one?).
  • Pragmatic Ambiguity & Sarcasm: The literal meaning diverges from speaker intent. "Oh, brilliant! My server just crashed again." An untrained model detects positive polarity from "brilliant", while the true sentiment is intensely negative.
  • High Dimensionality & Sparsity: Natural human vocabulary easily exceeds hundreds of thousands of words ($|V| \ge 100,000$). Each sentence uses only a minuscule fraction, resulting in extreme matrix sparsity ($> 99.8\%$).
  • Out-of-Vocabulary (OOV) & Slang: New terms, typos, and abbreviations emerge dynamically ("ngl", "goat", "rizz", "delulu"). Traditional static lexicons immediately break on unseen tokens.

2. Classical vs. Deep Learning NLP Taxonomies

NLP is divided into two operational paradigms. The foundational paradigm (covered in Track 1) focuses on fast, interpretable, deterministic feature extraction combined with statistical machine learning models:

Chapter 02 • Preprocessing

The Complete 10-Step Text Preprocessing Pipeline

Rigorous text cleaning, heuristic filtering, tokenization, and morphological normalization.

Garbage in, garbage out is nowhere more pronounced than in NLP. Raw real-world text gathered from the web, user forms, or Twitter is contaminated with markup, encoding artifacts, emoticons, and noise. Below is the production-grade 10-step cleaning pipeline taught by Akarsh Vyas:

The 10 Heuristic Preprocessing Stages

  1. Lowercasing / Case Normalization: Eliminates duplicate vocabulary entries for "Apple", "apple", and "APPLE".
  2. HTML Tag Stripping: Removes DOM elements (<p>, <div>, <br>) using regular expressions or BeautifulSoup.
  3. URL & Hyperlink Removal: Eliminates HTTP/HTTPS links that explode vocabulary without carrying semantic classification signal.
  4. Punctuation Removal: Strips punctuation symbols using string.punctuation to isolate clean linguistic tokens.
  5. Chat-Word & Slang Expansion: Maps informal acronyms ("idk" → "I do not know", "brb" → "be right back", "tbh" → "to be honest") to standard English.
  6. Spelling Correction: Corrects typographical errors using dictionary frequency or Levenshtein edit distance via TextBlob.
  7. Stopwords Filtering: Eliminates high-frequency grammatical glue words ("the", "is", "at", "which") that flood counts without distinct category signal. Caution: Never remove negation words ("not", "never", "no") during sentiment or emotion analysis!
  8. Emoji Handling: Either strips emojis completely or converts them into textual tokens (e.g. 😂 → "laughing face") using Python's emoji library.
  9. Tokenization: Segments character streams into discrete semantic chunks (words, punctuation, or subwords).
  10. Morphological Normalization (Stemming vs. Lemmatization):
    • Stemming: Fast, rule-based suffix chopping (Porter/Snowball). Often produces non-words (e.g., "university" → "univers").
    • Lemmatization: Context-aware vocabulary reduction using vocabulary lookups and Part-of-Speech tags (WordNet). Always produces valid canonical dictionary lemmas (e.g., "better" → "good").

Production Python Preprocessing Pipeline Code

import re
import string
import nltk
from nltk.corpus import stopwords
from nltk.stem import PorterStemmer, WordNetLemmatizer
from nltk.tokenize import word_tokenize

# Download required NLTK corpuses
nltk.download('punkt', quiet=True)
nltk.download('stopwords', quiet=True)
nltk.download('wordnet', quiet=True)

stemmer = PorterStemmer()
lemmatizer = WordNetLemmatizer()

# Custom Slang Mapping Dictionary
CHAT_WORDS = {
    "idk": "i do not know",
    "brb": "be right back",
    "tbh": "to be honest",
    "imo": "in my opinion",
    "fyi": "for your information"
}

def clean_text_pipeline(raw_text, use_lemmatizer=True):
    if not isinstance(raw_text, str):
        return ""
    
    # 1. Lowercasing
    text = raw_text.lower()
    
    # 2. HTML Tag Stripping
    text = re.sub(r'<.*?>', '', text)
    
    # 3. URL Removal
    text = re.sub(r'https?://\S+|www\.\S+', '', text)
    
    # 4. Chat Word Replacement
    words = text.split()
    words = [CHAT_WORDS.get(w, w) for w in words]
    text = " ".join(words)
    
    # 5. Punctuation Removal
    text = text.translate(str.maketrans('', '', string.punctuation))
    
    # 6. Tokenization
    tokens = word_tokenize(text)
    
    # 7. Stopword Filtering (Retaining critical negations)
    stop_words = set(stopwords.words('english')) - {'no', 'not', 'nor'}
    filtered_tokens = [w for w in tokens if w not in stop_words and w.isalpha()]
    
    # 8. Stemming / Lemmatization
    if use_lemmatizer:
        final_tokens = [lemmatizer.lemmatize(w) for w in filtered_tokens]
    else:
        final_tokens = [stemmer.stem(w) for w in filtered_tokens]
        
    return " ".join(final_tokens)

# Demonstration
sample = "<p>Check out https://akarsh.ai! TBH, I am not feeling good today... :( </p>"
print("Original:", sample)
print("Cleaned: ", clean_text_pipeline(sample))
# Output: "check tbh not feel good today"

Chapter 03 • Vectorization

Classical Vectorization: BoW, N-Grams & TF-IDF

Converting discrete unstructured character sequences into rigorous numeric vector spaces.

Machine learning algorithms perform numerical optimization over linear algebra matrices; they cannot process strings directly. Vectorization is the mathematical transformation mapping a textual document $d_i$ into a numeric vector $\mathbf{v}_i \in \mathbb{R}^{|V|}$.

1. One-Hot Encoding (OHE)

Each word in vocabulary $V$ is represented as a $|V|$-dimensional binary vector where exactly one index is 1 and all others are 0.

  • Critical Flaw 1: Massive Sparsity. If vocabulary has 50,000 words, a 10-word sentence requires a $10 imes 50,000$ matrix that is $99.98\%$ zeroes.
  • Critical Flaw 2: Orthogonality. Any two one-hot vectors $\mathbf{w}_i, \mathbf{w}_j$ have an inner product of zero: $\mathbf{w}_i \cdot \mathbf{w}_j = 0$. The model perceives zero similarity between "puppy" and "dog"!

2. Bag of Words (BoW / CountVectorizer)

The Bag of Words model constructs a global vocabulary $V = \{w_1, w_2, \dots, w_M\}$ from the entire corpus $D$. Each document $d$ is encoded as an $M$-dimensional vector containing the raw integer occurrence count of each vocabulary term:

Bag of Words Vector Formulation
$$\mathbf{v}_{ ext{BoW}}(d) = \left[ ext{tf}(w_1, d),\, ext{tf}(w_2, d),\, \dots,\, ext{tf}(w_M, d) ight]^T$$
Where $ ext{tf}(w_k, d)$ represents the raw count of word $w_k$ appearing in document $d$.

The N-Gram Extension

BoW discards word order completely (hence "bag"). To retain local contextual relationships, we introduce N-Grams (consecutive tuples of $n$ words):

  • Unigram ($n=1$): ["this", "movie", "is", "not", "good"] (loses negation context)
  • Bigram ($n=2$): ["this movie", "movie is", "is not", "not good"] (preserves "not good"!)
  • Trigram ($n=3$): ["this movie is", "movie is not", "is not good"]

3. TF-IDF (Term Frequency - Inverse Document Frequency)

BoW suffers from a major defect: frequent generic words dominate feature counts. If a word appears 100 times across every document in a legal corpus (e.g. "court", "lawyer"), it provides zero distinguishing power.

TF-IDF solves this by multiplying a local metric (Term Frequency) with a global penalization metric (Inverse Document Frequency):

TF-IDF Mathematical Definition
$$ ext{TF}(t, d) = rac{ ext{Count of } t ext{ in } d}{ ext{Total words in } d}$$ $$ ext{IDF}(t, D) = \log\left( rac{1 + N}{1 + |\,\{d \in D : t \in d\}\,| } ight) + 1$$ $$ ext{TF-IDF}(t, d, D) = ext{TF}(t, d) imes ext{IDF}(t, D)$$
$N$ is the total number of documents in the corpus. The smooth IDF formula (used in Scikit-Learn) adds 1 to avoid division by zero and log of zero.

Euclidean (L2) Vector Normalization

To ensure long documents do not dominate over short ones, Scikit-Learn applies L2 normalization to each document vector:

$$\mathbf{v}_{ ext{norm}} = rac{\mathbf{v}}{\|\mathbf{v}\|_2} = rac{\mathbf{v}}{\sqrt{\sum_{k} v_k^2}}$$ 
from sklearn.feature_extraction.text import TfidfVectorizer

corpus = [
    "I loved this incredible machine learning course.",
    "This machine learning course was so boring and dry.",
    "Completely loved the deep learning neural networks section."
]

vectorizer = TfidfVectorizer(ngram_range=(1, 2), max_features=10)
X = vectorizer.fit_transform(corpus)

print("Vocabulary Features:", vectorizer.get_feature_names_out())

Chapter 04 • Modeling

Machine Learning Classifiers for NLP

Multinomial Naive Bayes, Laplace smoothing derivation, and Logistic Regression on sparse text matrices.

Once text is transformed into TF-IDF vectors, we feed the matrix into supervised classification algorithms. In classical NLP, Multinomial Naive Bayes and Logistic Regression are the two canonical choices.

1. Multinomial Naive Bayes Formulation

Naive Bayes calculates the posterior probability of a class $C_k$ given document word vector $\mathbf{w} = (w_1, w_2, \dots, w_n)$ using Bayes' Theorem:

Bayes Theorem with Conditional Independence Assumption
$$P(C_k \mid w_1, \dots, w_n) \propto P(C_k) \prod_{i=1}^n P(w_i \mid C_k)$$
The "naive" assumption states that conditioned on class $C_k$, the probability of observing word $w_i$ is completely independent of word $w_j$. While linguistically false, this assumption performs remarkably well in practice.

Log-Space Transformation (Preventing Floating-Point Underflow)

Multiplying hundreds of small fractional probabilities produces floating-point underflow ($p o 0$). We convert the product into a sum of logarithms:

$$\hat{y} = rg\max_{C_k} \left[ \log P(C_k) + \sum_{i=1}^n \log P(w_i \mid C_k) ight]$$

Laplace Additive Smoothing ($lpha = 1$)

If an unseen test word appears that was never observed in class $C_k$ during training, $P(w_{ ext{unseen}} \mid C_k) = 0$. In an un-smoothed product, a single zero collapses the entire probability for that class to zero!

Laplace Smoothed Word Probability
$$P(w_i \mid C_k) = rac{N_{C_k, w_i} + lpha}{N_{C_k} + lpha |V|}$$
$N_{C_k, w_i}$ is the count of word $w_i$ in class $C_k$. $N_{C_k}$ is total words in class $C_k$. $|V|$ is the total vocabulary size. $lpha=1$ ensures every word has a strictly positive non-zero probability.

Hands-On Capstone Project: Real-Time Emotion Detection

Building, training, evaluating, and deploying a multi-class emotion classifier from scratch.

End-to-End Executable Project Implementation

import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.naive_bayes import MultinomialNB
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline
from sklearn.metrics import classification_report, confusion_matrix

# 1. Synthetic Representative Dataset (Mirroring Kaggle Emotion Dataset)
data = {
    'text': [
        "I feel so ecstatic and grateful for this incredible promotion today!",
        "I am so joyful and happy to see my family again after all these months.",
        "I feel deeply saddened and heartbroken by the tragic news.",
        "Everything feels depressing and sorrowful lately, nothing goes right.",
        "I am furious and outraged by the terrible service and rude behavior!",
        "My anger is boiling over, this unfair treatment is unacceptable.",
        "I am terrified of losing my job and terrified of what comes next.",
        "Heart pounding with dreadful fear walking through the dark alley.",
        "I love you with all my heart, you mean the world to me forever.",
        "Deeply in love and cherish every moment we spend together.",
        "I was utterly astonished and amazed by the unexpected surprise party!",
        "Shocked beyond belief, I never expected such a wonderful plot twist!"
    ] * 20,
    'emotion': [
        'joy', 'joy', 'sadness', 'sadness',
        'anger', 'anger', 'fear', 'fear',
        'love', 'love', 'surprise', 'surprise'
    ] * 20
}

df = pd.DataFrame(data)

# 2. Train/Test Stratified Split
X_train, X_test, y_train, y_test = train_test_split(
    df['text'], df['emotion'], test_size=0.25, random_state=42, stratify=df['emotion']
)

# 3. Scikit-Learn Pipeline Construction
emotion_pipeline = Pipeline([
    ('tfidf', TfidfVectorizer(
        ngram_range=(1, 2),
        max_features=5000,
        sublinear_tf=True
    )),
    ('classifier', MultinomialNB(alpha=0.5))
])

# 4. Model Training
emotion_pipeline.fit(X_train, y_train)

# 5. Performance Evaluation
y_pred = emotion_pipeline.predict(X_test)
print("=== CLASSIFICATION REPORT ===")
print(classification_report(y_test, y_pred))

# 6. Real-Time Inference Function with Class Probabilities
def predict_emotion(input_text):
    pred_label = emotion_pipeline.predict([input_text])[0]
    probs = emotion_pipeline.predict_proba([input_text])[0]
    classes = emotion_pipeline.classes_
    
    prob_dict = {cls: round(prob * 100, 2) for cls, prob in zip(classes, probs)}
    sorted_probs = sorted(prob_dict.items(), key=lambda x: x[1], reverse=True)
    
    print(f"\nInput: '{input_text}'")
    print(f"Predicted Emotion: {pred_label.upper()}")
    print("Probability Distribution:")
    for cls, pct in sorted_probs:
        bar = '█' * int(pct // 5)
        print(f"  {cls:<10} : {pct:>5.1f}% {bar}")

# Test real-time inference
predict_emotion("I cannot believe they cancelled my flight without warning, absolutely livid!")
predict_emotion("Holding my newborn baby girl for the very first time.")

🎓 Project Key Takeaways for Interviews

  • Sublinear TF: Setting sublinear_tf=True applies $1 + \log( ext{TF})$ instead of raw TF, which squashes the impact of words repeated multiple times in a single sentence.
  • Class Imbalance: In real Kaggle emotion sets, joy and sadness typically account for 65% of samples while surprise is only 3%. In production, always use stratify=y and evaluate with Macro F1-score rather than raw accuracy.

Chapter 07 • Word2Vec

Distributed Representations & Word2Vec

Dense geometric embeddings, Continuous Bag of Words (CBOW), and Skip-Gram neural architectures.

The fatal limitation of classical count-based methods (BoW, TF-IDF) is that words are treated as atomic, isolated symbols. In a TF-IDF matrix, the vectors for "hotel" and "motel" are as completely orthogonal and unrelated as the vectors for "hotel" and "submarine".

1. The Distributional Semantics Hypothesis

Formulated by British linguist J.R. Firth (1957): "You shall know a word by the company it keeps." Words that appear in similar linguistic contexts possess similar semantic meanings.

In 2013, Tomas Mikolov et al. at Google introduced Word2Vec: mapping each word to a dense continuous vector $\mathbf{v} \in \mathbb{R}^d$ (typically $d = 100$ to $300$), where semantic similarities correspond to geometric proximity in vector space!

Vector Arithmetic & Semantic Geometry
$$ ec{v}_{ ext{King}} - ec{v}_{ ext{Man}} + ec{v}_{ ext{Woman}} pprox ec{v}_{ ext{Queen}}$$ $$ ec{v}_{ ext{Paris}} - ec{v}_{ ext{France}} + ec{v}_{ ext{Japan}} pprox ec{v}_{ ext{Tokyo}}$$
The linear vector offset between "King" and "Queen" encodes gender, while the offset between "Paris" and "France" encodes capital-city relationships.

2. Cosine Similarity Metric

Because vectors live in dense continuous space, semantic closeness is quantified by the angle $ heta$ between vectors, completely invariant to magnitude:

Cosine Similarity Formula
$$ ext{CosineSim}(\mathbf{u}, \mathbf{v}) = rac{\mathbf{u} \cdot \mathbf{v}}{\|\mathbf{u}\|_2 \|\mathbf{v}\|_2} = rac{\sum_{i=1}^d u_i v_i}{\sqrt{\sum_{i=1}^d u_i^2} \sqrt{\sum_{i=1}^d v_i^2}}$$
Values range from $-1$ (opposite direction) to $0$ (orthogonal / unrelated) to $+1$ (identical direction / synonymous).

4. Pretrained Embeddings: GloVe and FastText

  • Stanford GloVe (Global Vectors): Trained by factorizing the global word-word co-occurrence matrix across the entire Wikipedia/Common Crawl corpus.

Chapter 08 • Document Embeddings

Document Embeddings: Average & TF-IDF Word2Vec

Aggregating word-level geometric representations into sentence and document-level vectors.

Word2Vec produces vectors for individual tokens. To classify an entire paragraph or document $d$, we must synthesize individual word vectors into a single fixed-length document vector $\mathbf{v}_d$.

1. Average Word2Vec

The simplest and most reliable approach computes the centroid (element-wise arithmetic mean) across all recognized words in the document:

Average Word2Vec Formula
$$\mathbf{v}_d = rac{1}{|d|} \sum_{w \in d} \mathbf{v}_w$$
Where $|d|$ is the count of words in document $d$ that exist in the Word2Vec vocabulary.

2. TF-IDF Weighted Word2Vec

Simple averaging gives equal voting weight to every word. A superior formulation weights each vector by its TF-IDF importance score, allowing salient keywords to pull the document vector in their direction:

TF-IDF Weighted Word2Vec Formula
$$\mathbf{v}_d = rac{\sum_{w \in d} ext{TF-IDF}(w, d) \cdot \mathbf{v}_w}{\sum_{w \in d} ext{TF-IDF}(w, d)}$$
High-value unique terms contribute heavily to the document centroid, while frequent generic words have negligible effect. 
import numpy as np
from gensim.models import Word2Vec

# Training custom Word2Vec on tokenized sentences
sentences = [
    ["deep", "learning", "neural", "networks", "revolutionized", "computer", "vision"],
    ["natural", "language", "processing", "uses", "dense", "word", "embeddings"],
    ["transformers", "and", "self", "attention", "dominate", "modern", "nlp"]
]

w2v_model = Word2Vec(sentences, vector_size=100, window=5, min_count=1, workers=4)

def get_average_word2vec(doc_tokens, model, vector_dim=100):
    valid_vectors = [model.wv[w] for w in doc_tokens if w in model.wv]
    if len(valid_vectors) == 0:
        return np.zeros(vector_dim)
    return np.mean(valid_vectors, axis=0)

doc = ["modern", "neural", "nlp"]
doc_vector = get_average_word2vec(doc, w2v_model)

Chapter 09 • Sequence Models

Sequence Modeling & POS Tagging with HMMs

Markov chains, transition/emission probability matrices, and optimal path decoding via the Viterbi Algorithm.

Bag of words completely destroys sequential grammar. In syntactic parsing, Part-of-Speech (POS) Tagging assigns grammatical categories (Noun, Verb, Adjective, etc.) to each token in a sentence.

Hidden Markov Models (HMM) for POS Tagging

In an HMM framework:

  • Observable States ($O$): The surface words in the sentence (e.g. "The", "bear", "can", "run").
  • Hidden States ($S$): The true grammatical POS tags (e.g. DET, NOUN, MODAL, VERB).
  • Transition Probability Matrix ($A$): Probability of moving from tag $t_{i-1}$ to tag $t_i$: $$A_{jk} = P(t_i = s_k \mid t_{i-1} = s_j)$$
  • Emission Probability Matrix ($B$): Probability of a tag emitting a specific word: $$B_{j}(w_k) = P(w_k \mid t_j)$$

The Viterbi Dynamic Programming Algorithm

Given an observed sentence of length $T$, brute-force evaluation of all possible tag combinations requires $O(|S|^T)$ exponential time. The Viterbi Algorithm solves this in $O(T \cdot |S|^2)$ polynomial time using dynamic programming:

Viterbi Recursive State Update
$$V_{t, k} = \max_{j} \left( V_{t-1, j} imes P(t_k \mid t_j) ight) imes P(w_t \mid t_k)$$
$V_{t, k}$ stores the maximum probability of the state sequence leading to hidden tag $k$ at time step $t$. Backpointers record the argmax index to reconstruct the optimal sequence.
Chapter 10 • Deep Learning

Transition to Deep Learning & Transformers

Recurrent Neural Networks, Vanishing Gradients, LSTMs, and the Attention Revolution.

As NLP progressed into complex tasks (Machine Translation, Text Summarization), statistical models gave way to deep sequence-to-sequence neural networks.

1. Recurrent Neural Networks (RNN) & Their Failure Mode

Standard RNNs maintain an internal hidden memory vector $h_t = anh(W_{hh} h_{t-1} + W_{xh} x_t)$ that updates sequentially across tokens.

  • The Vanishing Gradient Trap: During Backpropagation Through Time (BPTT), repeated matrix multiplications of weights $W_{hh} < 1$ cause error gradients to decay exponentially: $$ rac{\partial L}{\partial h_1} \propto \prod_{k=2}^T W_{hh}^T \longrightarrow 0$$ The network completely forgets dependencies beyond 8–10 tokens!

2. LSTMs and GRUs

Long Short-Term Memory (LSTM) networks introduce a dedicated Cell State ($\mathbf{c}_t$) highway regulated by three multiplicative sigmoid gates:

  • Forget Gate: $f_t = \sigma(W_f [h_{t-1}, x_t] + b_f)$ (What information to discard)
  • Input Gate: $i_t = \sigma(W_i [h_{t-1}, x_t] + b_i)$ (What new information to store)
  • Output Gate: $o_t = \sigma(W_o [h_{t-1}, x_t] + b_o)$ (What filtered state to output)

3. The Transformer Architecture & Self-Attention

In 2017, Vaswani et al. published "Attention Is All You Need", abolishing sequential recurrence in favor of parallelized matrix operations powered by Scaled Dot-Product Self-Attention:

Scaled Dot-Product Attention Equation
$$ ext{Attention}(Q, K, V) = ext{softmax}\left( rac{QK^T}{\sqrt{d_k}} ight) V$$
$Q$ (Queries), $K$ (Keys), and $V$ (Values) are linear projections of input embeddings. The dot product $QK^T$ computes pairwise semantic compatibility between every word in the sentence simultaneously. Dividing by $\sqrt{d_k}$ prevents large dot products from pushing softmax into vanishing gradient regions.

Top 15 Placement Interview Questions — NLP & Language AI

Curated from Google, Microsoft, Amazon, Walmart, and premier AI product engineering interviews. Click to reveal complete technical answers and formulas.

01Explain the fundamental difference between Stemming and Lemmatization. When would you prefer one over the other in production?

Answer:

  • Stemming is an algorithmic, rule-based heuristic that truncates affixes (prefixes/suffixes) from words using static lookups (e.g. Porter, Snowball stemmers). It operates without context or grammatical knowledge, often producing non-dictionary stems (e.g. "university" → "univers", "organization" → "organ").
  • Lemmatization performs full morphological analysis using a dictionary (WordNet) and Part-of-Speech (POS) tags to return the true base dictionary headword known as the lemma (e.g. "better" (with POS=adjective) → "good", "running" (POS=verb) → "run").
  • Production Preference: Use Stemming when latency is paramount and the task is simple query matching or search index retrieval where morphological exactness is secondary to speed. Use Lemmatization when semantic accuracy, text summarization, grammar correction, or sentiment nuance is critical.
02Why is the logarithm applied in the Inverse Document Frequency (IDF) formula? What breaks if we use raw inverse frequency?

Answer:

In a corpus of $N = 10,000,000$ documents, if a rare word appears in only 1 document, its raw inverse ratio is $ rac{N}{DF} = 10,000,000$. If another word appears in 1,000 documents, its raw ratio is $10,000$.

Using raw inverse ratios would give the first word a weighting that is 1,000 times larger than the second word! This exponential scale completely drowns out term frequency (TF), making rare typos completely dominate document vectors.

Taking the logarithm: $\log(10,000,000) pprox 7$, and $\log(10,000) pprox 4$. The logarithm applies sub-linear dampening, compressing astronomical frequency ranges into stable, balanced coefficients that complement term frequency.

03How does Laplace Additive Smoothing work in Multinomial Naive Bayes, and what catastrophic failure does it prevent?

Answer:

In standard maximum likelihood estimation, the probability of observing word $w$ in class $C$ is $P(w \mid C) = rac{ ext{count}(w, C)}{\sum_{w'} ext{count}(w', C)}$. If an unseen test word appears that never occurred in training for class $C$, $P(w \mid C) = 0$.

Because Naive Bayes multiplies conditional probabilities ($P(C) imes \prod_i P(w_i \mid C)$), a single zero collapses the entire probability for that class to absolute zero (Zero Probability Problem).

Laplace Smoothing ($lpha=1$): Adds pseudocount $lpha$ to numerator and $lpha |V|$ to denominator: $$P(w_i \mid C) = rac{N_{C, w_i} + 1}{N_C + |V|}$$ This guarantees every vocabulary token retains a small, non-zero probability.

04What are the three core architectural flaws of Bag-of-Words and TF-IDF representations?

Answer:

  1. Loss of Sequential Context (Word Order Ignored): "Dog bites man" and "Man bites dog" produce identical BoW/TF-IDF vectors despite conveying opposite real-world events.
  2. Orthogonality & Absence of Semantic Similarity: Every word is an independent axis. "Automobile" and "car" have an inner product of zero. The model cannot infer that two documents discussing "cars" and "automobiles" are conceptually related.
  3. Extreme Dimensionality & Sparsity: Vector length equals vocabulary size $|V|$. For $|V| = 80,000$, a 15-word tweet yields a vector that is $99.98\%$ zeroes, wasting GPU memory and causing overfitting.
05Compare Word2Vec CBOW vs. Skip-Gram. Which architecture performs better on rare words and why?

Answer:

Skip-Gram performs significantly better on rare words.

  • In CBOW, context word vectors are averaged together to predict the center target word. During this averaging step, rare words are completely smoothed out and overpowered by frequent context tokens.
  • In Skip-Gram, the center word is tasked with predicting each context word individually. Whenever a rare word appears as the center target, its embedding receives dedicated backpropagation gradient updates against all surrounding context words, preventing its gradient from being diluted.
06How does Facebook FastText solve the Out-of-Vocabulary (OOV) problem that breaks standard Word2Vec and GloVe?

Answer:

Standard Word2Vec and GloVe assign a single atomic vector to each complete word token. If an unseen word occurs at test time (e.g. "electrochemical"), the model returns a zero or random vector.

FastText treats words as bags of character n-grams with boundary brackets (e.g. for $n=3$, "where" → "<wh", "whe", "her", "ere", "re>" plus the special token "<where>"). The word embedding is the sum of all its subword character n-gram vectors.

When an Out-of-Vocabulary word or typo appears at inference, FastText decomposes it into familiar character subwords and synthesizes an accurate embedding from constituent morphological pieces!

07How do you calculate document embeddings using TF-IDF Weighted Word2Vec, and why is it superior to Average Word2Vec?

Answer:

Simple Average Word2Vec calculates $\mathbf{v}_d = rac{1}{|d|} \sum_{w \in d} \mathbf{v}_w$, assigning equal voting power to high-frequency filler words as to core domain keywords.

TF-IDF Weighted Word2Vec:

$$\mathbf{v}_d = rac{\sum_{w \in d} ext{TF-IDF}(w, d) \cdot \mathbf{v}_w}{\sum_{w \in d} ext{TF-IDF}(w, d)}$$

Words with high IDF (rare, discriminative topic words) receive massive coefficients, dynamically pulling the document centroid vector towards the authentic semantic intent of the text.

08Explain the working principle of the Viterbi algorithm in POS Tagging using Hidden Markov Models. What is its time complexity?

Answer:

The Viterbi algorithm is a dynamic programming technique used to find the most probable sequence of hidden states (POS tags) given an observed sequence of words.

At each time step $t$ and state $k$, Viterbi computes: $$V_{t, k} = \max_{j} \left( V_{t-1, j} imes A_{j, k} ight) imes B_k(w_t)$$ Where $A_{j, k}$ is tag transition probability and $B_k(w_t)$ is emission probability. Backpointers store the state index $j$ that yielded the maximum value.

Complexity: $O(T \cdot |S|^2)$ time and $O(T \cdot |S|)$ space, where $T$ is sentence length and $|S|$ is the count of distinct POS tags. This transforms an impossible $O(|S|^T)$ exponential problem into real-time linear computation.

09Why do standard RNNs suffer from vanishing gradients when processing long text sequences, and how do LSTMs resolve this?

Answer:

In standard RNNs, hidden state transitions apply $h_t = anh(W_{hh} h_{t-1} + W_{xh} x_t)$. During Backpropagation Through Time (BPTT), the gradient of loss $L$ with respect to early hidden state $h_1$ involves the product chain: $$ rac{\partial L}{\partial h_1} \propto \prod_{k=2}^T ext{diag}(1 - h_k^2) W_{hh}^T$$ Because the derivative of $ anh$ is bounded in $(0, 1]$ and eigenvalues of $W_{hh} < 1$, the gradient vanishes exponentially to 0 after 8–10 steps.

LSTM Solution: Introduces an additive Cell State ($\mathbf{c}_t = f_t \odot c_{t-1} + i_t \odot ilde{c}_t$). Gradient flow through the cell state contains an additive component $ rac{\partial c_t}{\partial c_{t-1}} = f_t$, providing an uninterrupted gradient highway across hundreds of tokens without exponential decay.

10Derive the Scaled Dot-Product Attention equation. Why do we divide by $\sqrt{d_k}$?

Answer:

The Scaled Dot-Product Attention formula is: $$ ext{Attention}(Q, K, V) = ext{softmax}\left( rac{QK^T}{\sqrt{d_k}} ight) V$$

Why divide by $\sqrt{d_k}$?

Assume components of query $q$ and key $k$ are independent random variables with mean 0 and variance 1. The dot product is $q \cdot k = \sum_{i=1}^{d_k} q_i k_i$. The mean of the dot product is 0, but its variance is $d_k$.

For large projection dimensions (e.g. $d_k = 64$ or $128$), the variance is $64$, meaning dot products become very large in magnitude. Large positive inputs into $ ext{softmax}(z)$ push it into regions with near-zero gradients ($ ext{softmax}'(z) o 0$), causing severe gradient vanishing during training.

Dividing by $\sqrt{d_k}$ scales the variance back down to exactly $1$, stabilizing softmax gradients.

11How do you handle severe class imbalance in text classification (e.g., Rare emotion detection or SMS spam)?

Answer:

  • Stratified Sampling: Use StratifiedKFold or train_test_split(stratify=y) to ensure train and test sets have identical class proportions.
  • Loss Function Weighting: Apply class weights inversely proportional to class frequency: $w_c = rac{N}{|C| \cdot N_c}$ (e.g. class_weight='balanced' in Scikit-Learn or Focal Loss in deep learning).
  • Data Augmentation / Synthetic Sampling: SMOTE on vector embeddings, or contextual back-translation (English → German → English) to generate diverse minority samples.
  • Evaluation Metric Shift: Never use raw accuracy! Use Precision-Recall AUC (PR-AUC), Macro F1-score, and cost-weighted confusion matrices.
12What is Subword Tokenization (BPE, WordPiece) and why is it preferred by modern LLMs over word-level tokenization?

Answer:

Word-level tokenization requires an enormous vocabulary ($> 500,000$ words) yet still fails on typos, slang, and compound terms. Character-level tokenization solves OOV but creates absurdly long sequences that destroy computational efficiency.

Subword Tokenization (Byte-Pair Encoding / WordPiece): Begins with base characters and iteratively merges the most frequently co-occurring pairs into subwords. Common words remain intact ("the", "cat"), while rare or novel words are segmented into subword stems ("unfriendly" → "un", "friend", "ly").

This bounds vocabulary size to a compact $30,000 - 50,000$ tokens while completely eliminating the Out-of-Vocabulary (OOV) failure mode.

13What is the difference between Extractive and Abstractive text summarization? Which techniques power each?

Answer:

  • Extractive Summarization: Selects and extracts the most salient existing sentences verbatim from the original text without generating any new vocabulary. Powered by graph ranking algorithms like TextRank (PageRank over cosine similarity of sentence embeddings) or supervised sentence scoring.
  • Abstractive Summarization: Reads the original text, forms an internal semantic representation, and generates novel paraphrased sentences from scratch (like a human writing a summary). Powered by encoder-decoder transformers (BART, T5, Pegasus) and autoregressive LLMs.
14How does the Attention mechanism in Seq2Seq models overcome the Information Bottleneck problem?

Answer:

In standard encoder-decoder Seq2Seq networks, the encoder compresses an entire input sentence of arbitrary length into a single fixed-size vector $h_T$ (the context vector). Trying to force a 50-word sentence into a single 512-dimensional vector creates a severe information bottleneck that drops early details.

Attention Solution: The encoder preserves the hidden states $h_1, h_2, \dots, h_T$ from every single time step. When generating output token $y_t$, the decoder calculates an attention weight distribution $lpha_{t, i}$ over all encoder states, computing a dynamic context vector $c_t = \sum_{i=1}^T lpha_{t, i} h_i$. The decoder directly accesses any source word across the entire sentence.

15How would you architect a production Duplicate Question Detection system for a platform like Quora handling 50M daily queries?

Answer:

A production architecture uses a two-tier Retrieve-and-Rerank system:

  1. Stage 1: Candidate Retrieval (High Recall, < 10ms):
    • Convert question into dense embedding via bi-encoder (MiniLM / Sentence-BERT).
    • Perform Approximate Nearest Neighbor (ANN) search over 100M existing question embeddings using FAISS or HNSW vector database.
    • Retrieve top 100 candidate duplicates.
  2. Stage 2: Precision Re-Ranking (High Precision, < 30ms):
    • Pass question pair and top 100 candidates through a cross-encoder or gradient-boosted tree (XGBoost) trained on fuzzy token matching, length differentials, and Word Mover's Distance.
    • Sort by predicted duplicate probability; if top score exceeds threshold $0.85$, trigger duplicate merge.

NLP 1. Derive TF-IDF and explain why sublinear TF scaling is needed.
Derivation Vector Space ▼

TF-IDF(t, d, D) = TF(t, d) * IDF(t, D), where IDF(t, D) = log( (1 + |D|) / (1 + DF(t)) ) + 1.

Standard term frequency assumes twenty occurrences of a term convey 20x the relevance of one occurrence. Sublinear TF scaling replaces raw count with 1 + log(TF), dampening repeated occurrences.

NLP 2. Compare CBOW and Skip-Gram architectures in Word2Vec.
Embeddings Word2Vec ▼

Continuous Bag-of-Words (CBOW): Predicts target center word w_t given context window words. Faster to train, higher accuracy on frequent words due to averaging context.

Skip-Gram: Predicts surrounding context words given center word w_t. Slower to train, but excels on small datasets and rare words because every context-target pair is treated as a distinct training instance.

NLP 3. Explain Byte Pair Encoding (BPE) subword tokenization.
Tokenization LLMs ▼

BPE starts with a character vocabulary. It iteratively finds the most frequently occurring adjacent pair of tokens across the corpus and merges them into a new single token until the vocabulary reaches target size V. Eliminates Out-Of-Vocabulary (OOV) errors while keeping vocabulary compact.

DSA 1. What is the Two Pointers pattern? Give 2 classic problems.
Pattern 1 NeetCode 150 ▼

The Two Pointers pattern uses two index pointers traversing an array/linked list from opposite ends (inward convergence) or in the same direction at varying rates, converting quadratic $O(N^2)$ brute-force solutions into optimal $O(N)$ linear scans.

Classic Problem 1 • Two Sum II - Input Array Is Sorted (LeetCode 167):

def twoSum(numbers: list[int], target: int) -> list[int]:
    left, right = 0, len(numbers) - 1
    while left < right:
        curr_sum = numbers[left] + numbers[right]
        if curr_sum == target: return [left + 1, right + 1] # 1-indexed
        elif curr_sum < target: left += 1
        else: right -= 1
    return []

Classic Problem 2 • Container With Most Water (LeetCode 11): Start at left = 0, right = n - 1. Compute area $(R - L) \times \min(H[L], H[R])$, then advance the pointer with the shorter wall inwards.

Time: O(N) Space: O(1) auxiliary
DSA 2. Explain Sliding Window technique and when to use it.
Pattern 2 NeetCode 150 ▼

The Sliding Window pattern maintains a continuous subsegment $[L, R]$ over an array or string that dynamically expands and contracts to maintain a desired invariant, avoiding recomputing overlapping subproblems.

# Longest Substring Without Repeating Characters (LeetCode 3)
def lengthOfLongestSubstring(s: str) -> int:
    char_map = {}
    left = max_len = 0
    for right, char in enumerate(s):
        if char in char_map and char_map[char] >= left:
            left = char_map[char] + 1
        char_map[char] = right
        max_len = max(max_len, right - left + 1)
    return max_len
Time: O(N) linear Space: O(min(N, alphabet_size))
DSA 3. What is Binary Search? When is it applicable beyond sorted arrays?
Pattern 3 NeetCode 150 ▼

Binary Search cuts the search space in half at each iteration in $O(\log N)$ time. Beyond sorted arrays, it applies whenever there is a Monotonic Decision Function $P(x) \in \{\text{False}, \dots, \text{False}, \text{True}, \dots, \text{True}\}$.

# Koko Eating Bananas (LeetCode 875)
def minEatingSpeed(piles: list[int], h: int) -> int:
    left, right = 1, max(piles)
    ans = right
    while left <= right:
        mid = (left + right) // 2
        hours = sum((p + mid - 1) // mid for p in piles)
        if hours <= h:
            ans = mid
            right = mid - 1
        else:
            left = mid + 1
    return ans
Time: O(N * log(max_pile)) Space: O(1)
DSA 4. Explain Fast & Slow Pointers (Floyd's Tortoise and Hare).
Pattern 4 Linked Lists ▼

Two pointers move at different speeds (slow = 1 step, fast = 2 steps). If there is a cycle, fast will lap slow. To find the cycle entry node: reset slow to head, then advance both 1 step per iteration until they meet.

Time: O(N) Space: O(1) auxiliary
DSA 5. What is the Monotonic Stack pattern and how does it guarantee O(N)?
Pattern 5 Stack ▼

A Monotonic Stack maintains elements in strictly ascending or descending order. Elements that violate order are popped. Because each index is pushed at most once and popped at most once, the total operations across all loops is bounded by $2N$, guaranteeing strict $O(N)$ amortized time.
