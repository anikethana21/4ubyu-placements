CPU scheduling interview problems are intensely quantitative. You will be given a table of 4 to 5 processes with arrival times, burst times, and priorities, and asked to compute exact Completion Time, Turnaround Time, and Waiting Time across FCFS, SJF, SRTF, and Round Robin using clear Gantt Charts.

3.1 Scheduling Objectives & Criteria Metrics

The CPU scheduler is the heart of multiprogramming. Since real-world processes alternate between CPU Bursts (executing code) and I/O Bursts (waiting for network, disk, or user input), scheduling maximizes CPU utilization by giving the CPU to another ready process whenever the current process enters an I/O wait state (⏱️ 04:44).

The 5 Golden Scheduling Performance Metrics:

  1. CPU Utilization: The percentage of total time the CPU is actively performing user or system computation (Goal: Maximize, practically 40% to 90%).
  2. Throughput: The number of complete processes executed per unit time (Goal: Maximize).
  3. Turnaround Time (TAT): The total elapsed time from the moment a process is submitted until its complete termination: $$\text{TAT} = \text{Completion Time (CT)} - \text{Arrival Time (AT)}$$ (Goal: Minimize).
  4. Waiting Time (WT): The cumulative time a process spends waiting in the Ready Queue: $$\text{WT} = \text{Turnaround Time (TAT)} - \text{Burst Time (BT)}$$ (Goal: Minimize).
  5. Response Time (RT): The time elapsed between process arrival and its very first execution on the CPU: $$\text{RT} = \text{Time of First CPU Dispatch} - \text{Arrival Time (AT)}$$ (Goal: Minimize; crucial for interactive UX).

3.2 Scheduler Taxonomy & Dispatcher Role

An operating system utilizes three distinct types of schedulers acting at different operational timescales (⏱️ 07:33):

  • Long-Term Scheduler (Job Scheduler): Selects processes from secondary storage (pool of batch jobs) and loads them into primary RAM ready queue. Regulates the Degree of Multiprogramming (total processes in memory). Invoked infrequently (seconds to minutes).
  • Short-Term Scheduler (CPU Scheduler): Selects which in-memory ready process is allocated the physical CPU. Invoked very frequently (every 10 to 100 milliseconds), hence must be exceptionally fast.
  • Medium-Term Scheduler (Swapper): Handles swapping out processes from RAM to Swap disk during severe memory pressure, and swapping them back when RAM frees up.
  • Dispatcher: The low-level kernel module that physically performs the context switch, switches the CPU to user mode, and jumps to the proper location in the user program. The elapsed time taken by the dispatcher to halt one process and start another is called Dispatch Latency.

3.3 Preemptive vs. Non-Preemptive Scheduling

  • Non-Preemptive Scheduling: Once a process is allocated the CPU, it holds the CPU until it voluntarily yields control—either by terminating (exit()) or by requesting I/O (transition to Waiting state). No timer interrupts can forcibly take the CPU away.
    Pros: Simple, low overhead, deterministic.
    Cons: Poor interactive response, vulnerable to rogue infinite loops.
  • Preemptive Scheduling: The OS kernel can forcibly interrupt and confiscate the CPU from an actively running process (e.g., when a higher-priority job arrives or the hardware timer interrupt signals time slice expiration).
    Pros: Excellent responsiveness, prevents starvation in interactive environments.
    Cons: Incurs higher context switch overhead; requires synchronization locks on shared kernel data structures to prevent race conditions.

3.4 First-Come, First-Served (FCFS) Scheduling

The simplest scheduling algorithm. Implemented via a standard FIFO queue (⏱️ 14:26). Non-preemptive.

The Convoy Effect Hazard:

If a massive CPU-bound process arrives first, all short, interactive I/O-bound processes are trapped behind it in the ready queue. While the giant process runs on CPU, the I/O devices sit idle. When the giant process finally blocks for I/O, all short processes quickly blast through CPU and block for I/O, leaving the CPU idle. This severe degradation in device and CPU utilization is called the Convoy Effect.

3.5 Shortest Job First (SJF) & Shortest Remaining Time First (SRTF)

Assigns the CPU to the process with the smallest subsequent CPU burst length (⏱️ 15:28).

  • Non-Preemptive SJF: Once granted, the process runs to completion of its burst. Provably achieves the minimal average waiting time among all non-preemptive algorithms.
  • Preemptive SJF (SRTF): If a new process arrives with a remaining CPU burst shorter than the remaining burst of the currently running process, the current process is immediately preempted.

Burst Time Estimation via Exponential Smoothing:

Because the OS cannot know future CPU bursts in advance, it predicts the next burst $\tau_{n+1}$ using past historical burst $t_n$ via exponential averaging:

$$\tau_{n+1} = \alpha t_n + (1 - \alpha) \tau_n \quad \text{where } 0 \le \alpha \le 1$$

Typically $\alpha = 0.5$, balancing recent behavior with long-term historical baseline.

3.7 Round Robin (RR) Scheduling

Designed specifically for time-sharing interactive systems (⏱️ 30:47). Each process is allocated a small unit of CPU time called a Time Quantum ($q$) or time slice (typically 10 to 100 ms). Processes are held in a circular FIFO queue.

The Time Quantum Dilemma:

  • If $q \to \infty$: Round Robin degenerates into FCFS, suffering from the Convoy Effect.
  • If $q \to 0$: Round Robin approaches Processor Sharing, where $n$ processes run at $1/n$ speed, but the system spends nearly 100% of CPU time executing context switches, collapsing throughput.
  • Rule of Thumb: Approximately 80% of CPU bursts should be shorter than the time quantum $q$ to minimize context switches while preserving rapid interactive response.

3.8 Priority Scheduling & The Aging Mitigation

Each process is assigned a priority integer $p$. The CPU is allocated to the highest-priority process (⏱️ 34:28).

  • Starvation (Indefinite Blocking): A low-priority process may sit in the ready queue indefinitely if a steady stream of higher-priority processes keeps arriving. (Legendary real-world case: When the IBM 7094 at MIT was shut down in 1973, a low-priority job submitted in 1967 was discovered still waiting!).
  • Aging Solution: A technique of gradually incrementing the priority of processes that wait in the system for long durations. Eventually, any aged process achieves the highest priority and is guaranteed CPU dispatch.
