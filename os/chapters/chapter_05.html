5.2 Address Binding: Compile-Time, Load-Time & Execution-Time

Before a program can execute, its instructions and variables must be bound to physical memory addresses (⏱️ 14:36):

  • Compile-Time Binding: If it is known at compile time where the process will reside in memory, absolute physical code is generated (e.g., MS-DOS .COM files). If starting location changes, the entire code must be recompiled.
  • Load-Time Binding: Compiler generates relocatable code. Final physical binding is delayed until the loader places the program into memory. If the process is swapped out and reloaded at a different physical base, addresses are invalid.
  • Execution-Time (Run-Time) Binding: Binding is delayed until the exact instant the instruction is executed by the CPU. Requires hardware support: the Memory Management Unit (MMU) with dynamic relocation base and limit registers. This is the universal standard in all modern multi-tasking operating systems.

5.3 Contiguous Memory Allocation & Fragmentation

In early multiprogramming systems, each process was loaded into a single contiguous block of physical RAM (⏱️ 17:25):

1. Fixed Partitioning (Multiprogramming with Fixed Tasks - MFT):

  • RAM is divided into fixed-sized partitions at boot time.
  • Internal Fragmentation: Occurs when the memory allocated to a process is slightly larger than the memory requested by the process. The unused space within the allocated partition is wasted and cannot be used by other processes.

2. Variable Partitioning (Multiprogramming with Variable Tasks - MVT):

  • Partitions are created dynamically to match the exact size requested by incoming processes.
  • External Fragmentation: As processes terminate and leave holes in RAM, the total free memory across the system is sufficient to satisfy an incoming request, but it is broken up into small, non-contiguous fragments.
  • Compaction: Moving all allocated blocks to one end of memory to coalesce scattered holes into one large block. Heavy CPU and bus overhead; only possible if run-time dynamic relocation is supported.

Dynamic Storage Allocation Strategies:

  • First-Fit: Allocate the first available hole that is large enough. Search stops immediately upon finding a valid hole. (Fastest, very efficient in practice).
  • Best-Fit: Allocate the smallest hole that is large enough. Requires searching the entire free list (unless sorted). Leaves behind tiny, unusable leftover holes.
  • Worst-Fit: Allocate the largest available hole. Requires searching entire list. Leaves behind largest leftover hole, which may be useful for subsequent allocations. (Performs worst in practice).

5.4 Segmentation: Programmer-Centric Logical Architecture

A user program does not view memory as a linear array of bytes; rather, it views memory as a collection of variable-length logical segments: the main function, helper routines, stack, heap, and symbol tables (⏱️ 21:32).

Hardware Address Translation in Segmentation:

A logical address is a tuple $\langle s, d \rangle$, where $s$ is the Segment Number and $d$ is the Segment Offset:

graph TD LogicalAddr["Logical Address: <Segment s, Offset d>"] --> Split[Split s and d] Split --> CheckLimit{"Is d < Limit?"} CheckLimit -->|No| Trap["Trap: Segmentation Fault (Addressing Error)"] CheckLimit -->|Yes| Adder["Adder: Base Address + d"] Adder --> PhysicalMem["Physical Memory RAM Address"] ST["Segment Table (Base, Limit)"] -.->|Look up entry s| CheckLimit ST -.->|Fetch Base| Adder
  • The segment number $s$ indexes into the Segment Table.
  • The hardware checks: if $d \ge \text{Limit}$, the MMU triggers a CPU trap (Segmentation Fault).
  • Otherwise, $\text{Physical Address} = \text{Base} + d$.
  • Limitation: Since segments vary in length, allocation of segments in physical memory still suffers from External Fragmentation.

5.5 Paging: The Universal Non-Contiguous Solution

Paging breaks physical memory and logical address space into fixed-sized chunks, eliminating external fragmentation completely (⏱️ 26:15):

  • Frames: Physical memory is divided into fixed-sized blocks called Frames (typically 4 KB).
  • Pages: Logical address space is divided into blocks of the exact same size called Pages.
  • Any free physical frame can be assigned to any page of any process.

Mathematical Address Translation in Paging:

Let the virtual address space be $2^n$ bytes and page size be $2^m$ bytes:

  • The higher $n - m$ bits represent the Page Number ($p$).
  • The lower $m$ bits represent the Page Offset ($d$) within the page.
graph LR VAddr["Virtual Address: [Page p (n-m bits)] | [Offset d (m bits)]"] VAddr --> PT["Page Table (Indexed by p)"] PT --> FrameVal["Extract Frame Number f"] FrameVal --> PAddr["Physical Address: [Frame f] | [Offset d]"]

Solved Concrete Interview Example:

Problem: Consider a 32-bit system with a 4 KB page size. What is the breakdown of the logical address, and how large is a linear Page Table assuming each Page Table Entry (PTE) is 4 bytes?

  • Page size $= 4 \text{ KB} = 2^{12} \text{ bytes} \implies m = 12 \text{ bits}$ for Page Offset ($d$).
  • Virtual address space $= 32 \text{ bits} \implies n = 32 \text{ bits}$.
  • Page Number bits $= n - m = 32 - 12 = 20 \text{ bits}$.
  • Total pages per process $= 2^{20} = 1,048,576 \text{ pages}$.
  • Page Table Size $= 2^{20} \text{ entries} \times 4 \text{ bytes/entry} = 4 \text{ MB per process!}$

Internal Fragmentation in Paging: Paging completely eliminates External Fragmentation. However, it incurs slight Internal Fragmentation on the very last page of a process (on average, half a page $\approx 2 \text{ KB}$).
