Core Interview Numericals

In technical interviews for systems engineering roles, candidates must know how to calculate Effective Memory Access Time (EMAT) with TLB hit ratios, detail the exact 7-step hardware/kernel page fault routine, trace Belady's Anomaly in FIFO replacement with reference strings, and explain the working set model for Thrashing prevention.

6.1 Translation Lookaside Buffer (TLB) & EMAT Calculations

In basic paging, every memory reference requires two physical RAM accesses: first to read the Page Table Entry (PTE) from RAM, and second to read/write the actual operand. This doubles memory latency and halves processor throughput (⏱️ 33:37).

The Translation Lookaside Buffer (TLB) is an associative hardware cache embedded directly inside the Memory Management Unit (MMU) that stores recent $\langle \text{Page Number}, \text{Frame Number} \rangle$ translations.

The Complete EMAT Formula:

Let $h$ be the TLB Hit Ratio ($0 \le h \le 1$), $t_{\text{tlb}}$ be the TLB search time, and $t_{\text{mem}}$ be the physical RAM access time:

$$\text{EMAT} = h \cdot (t_{\text{tlb}} + t_{\text{mem}}) + (1 - h) \cdot (t_{\text{tlb}} + 2 \cdot t_{\text{mem}})$$

Solved Placement Numerical:

Given: TLB access time $t_{\text{tlb}} = 10 \text{ ns}$, RAM access time $t_{\text{mem}} = 100 \text{ ns}$, TLB Hit Ratio $h = 95\% = 0.95$.

$$\text{On TLB Hit:} \quad 10 + 100 = 110 \text{ ns}$$

$$\text{On TLB Miss:} \quad 10 + 100 (\text{page table}) + 100 (\text{data}) = 210 \text{ ns}$$

$$\text{EMAT} = 0.95 \times 110 + 0.05 \times 210 = 104.5 + 10.5 = 115 \text{ ns}$$

Notice that with a 95% hit ratio, effective access slows from 100 ns to only 115 ns (a mere 15% slowdown instead of a 100% doubling!).

6.2 Virtual Memory & Demand Paging Mechanics

Virtual Memory decouples the logical address space perceived by user programs from physical RAM capacity (⏱️ 37:27). An application can allocate a 64 GB address space on a machine with only 8 GB of physical RAM.

Demand Paging & The Valid-Invalid Bit:

Under Demand Paging, pages are not preloaded into RAM at startup. Pages are loaded lazily only when the executing CPU actively references an instruction or data byte residing on that page.

  • Each entry in the Page Table includes a Valid-Invalid Bit ($v/i$):
    • Valid (v): The page is legally present in physical RAM. Translation proceeds immediately at hardware speed.
    • Invalid (i): The page is either outside the legal address space of the process, or is a valid page currently residing on secondary swap storage. Access triggers a Page Fault.

6.3 The 7-Step Page Fault Handling Routine

When the CPU attempts to access an address marked with an invalid bit, the MMU cannot complete the translation and raises a hardware trap to the OS kernel (⏱️ 39:50):

Page Fault Overhead Impact:

Disk I/O latency is approximately $8 \text{ ms} = 8,000,000 \text{ ns}$, whereas RAM access is $100 \text{ ns}$. If the page fault rate is denoted $p$, the effective access time is:

$$\text{EAT} = (1 - p) \cdot 100 \text{ ns} + p \cdot 8,000,000 \text{ ns}$$

Even if only 1 out of 100,000 accesses ($p = 0.00001$) triggers a page fault, memory access speed slows down by almost a factor of two! Hence, optimal page replacement algorithms are critical.

6.4 Page Replacement Algorithms

When a page fault occurs and all physical frames in RAM are occupied, the OS must select a victim frame to page out to disk (⏱️ 48:20):

1. First-In, First-Out (FIFO) & Belady's Anomaly:

The oldest loaded page in memory is chosen as victim.

Belady's Anomaly Defined

Normally, providing more physical RAM frames reduces the number of page faults. In FIFO Page Replacement, however, increasing the number of allocated physical frames can paradoxically increase the total number of page faults for certain reference strings! (e.g., Reference string: 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 yields 9 faults with 3 frames, but 10 faults with 4 frames!). Stack-based algorithms (OPT, LRU) are provably immune to Belady's Anomaly.

2. Optimal Page Replacement (OPT / MIN):

Replace the page that will not be referenced for the longest duration of time in the future. Provably guarantees the lowest possible page fault rate for any fixed number of frames. However, it is unimplementable in general-purpose systems because the OS cannot foresee the future. It serves as an optimal theoretical upper bound benchmark for evaluating practical algorithms.

3. Least Recently Used (LRU) Algorithm:

Approximates the Optimal algorithm by using the recent past as an approximation of the near future: replace the page that has not been referenced for the longest period of time (⏱️ 52:05).

  • Counter / Timestamp Implementation: Every page table entry contains a time-of-use field. On every memory access, copy CPU clock into the PTE. On replacement, scan all entries for smallest time value. High overhead ($O(N)$ scan).
  • Doubly-Linked List Stack: Maintain a stack of page numbers. Whenever a page is accessed, unlink it and move it to the top of the stack. The bottom of the stack is always the LRU victim frame ($O(1)$ replacement, but memory pointer updates on every access).

4. Clock / Second-Chance Algorithm:

Hardware approximation of LRU. Uses a circular queue and a single Reference Bit per frame:

  • When a page is accessed, hardware sets Reference Bit $= 1$.
  • When replacement is needed, the pointer moves circularly through the frames:
    • If Reference Bit $== 1$: Clear bit to $0$ and advance pointer (gives page a second chance).
    • If Reference Bit $== 0$: Select this frame as victim immediately!

6.5 Thrashing & The Working Set Model

If a process does not have enough physical frames allocated to hold its currently active working pages, it faults rapidly. The CPU scheduler sees processes blocking on I/O, assumes the CPU is underutilized, and increases the Degree of Multiprogramming by admitting more processes into RAM. This further starves existing processes of frames, plunging the system into Thrashing: a pathological state where the computer spends nearly 100% of its time swapping pages in and out of disk, while productive CPU utilization collapses to near zero (⏱️ 58:20).

Solution: The Working Set Model ($W(t, \Delta)$):

Peter Denning's Working Set Model defines the working set of a process as the set of distinct pages referenced in the most recent $\Delta$ page references (the Working Set Window). The OS calculates total demand $D = \sum |W_i|$. If $D > \text{Total Physical Frames}$, the OS immediately suspends/swaps out an entire process to free up frames, guaranteeing thrashing never occurs.
