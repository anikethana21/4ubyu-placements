Why This Chapter is Critical

While the video playlist covers core processes, scheduling, memory, deadlocks, and synchronization in masterclass depth, product companies (Google, Microsoft, Meta, Uber, Adobe) frequently test these four additional high-frequency pillars: Thread Models, Inter-Process Communication (IPC), Linux File Systems (Inodes), and Disk Scheduling algorithms.

9.1 Threads vs. Processes

A Thread is the fundamental unit of CPU utilization. It represents an independent thread of execution within a parent process.

Attribute Process Thread (Lightweight Process - LWP)
Address SpaceIsolated private virtual address space.Shares Code, Data, and Heap with peer threads in same process.
Private StateAll memory segments, PCB, file table.Private Stack, Program Counter (PC), and CPU Registers only.
Creation OverheadHigh; involves page table creation and memory mapping.Low (10x faster); only requires allocating a private stack.

User-Level Threads (ULT) vs. Kernel-Level Threads (KLT):

  • User-Level Threads (Many-to-One Model): Managed completely by user-space runtime thread library (e.g., Green threads). Kernel is completely unaware of thread existence. Switching threads does not require kernel mode trap.
    Flaw: If one ULT makes a blocking system call (e.g., disk read), the entire process and all peer threads block! Cannot run in parallel on multicore CPUs.
  • Kernel-Level Threads (One-to-One Model): Supported and scheduled directly by the OS kernel (e.g., Linux pthreads, Windows threads). Each user thread maps to a distinct kernel thread. True multicore hardware parallelism; if one thread blocks, others continue executing. Modern standard.

9.2 Inter-Process Communication (IPC) Mechanisms

Because processes run in isolated address spaces, they must use explicit IPC mechanisms to exchange data:

  1. Ordinary Pipes: Unidirectional byte stream for parent-child processes. Controlled via file descriptors fd[0] (read) and fd[1] (write). Exists only while processes live.
  2. Named Pipes (FIFOs): Bidirectional pipe with a directory entry on disk (mkfifo). Unrelated processes can communicate by opening the FIFO file.
  3. Shared Memory: Fastest IPC mechanism. OS maps a common physical memory region into the virtual address spaces of both processes. Processes read and write at raw RAM bus speed without kernel intervention (requires semaphores to coordinate access).
  4. Message Queues: Kernel-managed linked list of messages. Processes deposit and retrieve structured messages. Asynchronous and safe, but requires kernel mode transitions.
  5. Network Sockets: Endpoint communication across network boundaries (TCP/IP) or local loopback (UNIX Domain Sockets). Universal for microservices and distributed systems.

9.3 Linux File System Architecture & Inodes

The Linux Virtual File System (VFS) abstracts all physical storage devices as files ("Everything is a file" philosophy):

  • Superblock: Stores metadata about the overall filesystem (filesystem type, size, total block count, free block count, mount status).
  • Inode (Index Node): The fundamental metadata record for an individual file. Stores:
    • File type and permissions (rwxr-xr-x).
    • Owner User ID (UID) and Group ID (GID).
    • File size in bytes.
    • Timestamps: Access time (atime), Modification time (mtime), Change time (ctime).
    • Direct and Indirect Block Pointers pointing to actual data blocks on disk.
    • Crucial Note: The Inode does NOT store the file name! Directory entries map file names to Inode numbers.
  • Hard Link vs. Soft (Symbolic) Link:
    • Hard Link: An additional directory entry pointing to the exact same Inode. Deleting the original file does not delete the data until all hard links (link count $== 0$) are removed. Cannot link across different filesystems.
    • Soft Link (Symlink): A unique file with its own distinct Inode whose data block contains the string path of the target file. If original file is deleted, the symlink becomes a dangling/broken link. Works across filesystems.

9.4 Disk Scheduling Algorithms

Minimizes mechanical disk head movement (Seek Time) on traditional Hard Disk Drives (HDDs):

  • First-Come First-Served (FCFS): Requests serviced in order of arrival. Simple, but incurs massive head swings across the disk platters.
  • Shortest Seek Time First (SSTF): Selects the request with the minimum seek time from the current head position. Minimizes average seek time, but causes Starvation for requests at extreme cylinder edges.
  • SCAN (Elevator Algorithm): Disk arm moves in one direction servicing all requests until it hits the end cylinder of the disk, then reverses direction servicing requests on the way back. Eliminates starvation.
  • C-SCAN (Circular SCAN): Moves in one direction servicing requests until reaching the end, then immediately returns to the beginning of the disk without servicing requests on the return trip. Provides uniform waiting time.
  • LOOK and C-LOOK: Practical variants of SCAN and C-SCAN. The arm moves only as far as the final request in each direction, reversing without going all the way to the physical boundary cylinder of the disk.

9.5 Top 30 High-Frequency Placement Interview Questions

Q1: What is the main difference between a process and a thread?

A process is an isolated program in execution with its own virtual address space, PCB, and resources. A thread is an execution unit within a process sharing the code, data, and heap segments, while maintaining its own private stack, registers, and program counter.

Q2: What happens during a Context Switch?

The OS saves the CPU registers, program counter, and stack pointer of the active process into its PCB in kernel memory, updates its state to Ready or Waiting, selects another process from the Ready Queue, switches memory page table registers (CR3), and restores the saved registers of the new process.

Q3: Why is Peterson's Algorithm not sufficient on modern hardware?

Modern multi-core processors use instruction pipelining, speculative execution, out-of-order execution, and store buffers, which can reorder read/write operations on memory, breaking software-only synchronization assumptions unless hardware memory fences/barriers are used.

Q4: What is Belady's Anomaly and which algorithms exhibit it?

Belady's Anomaly is the phenomenon where increasing the number of physical page frames allocated to a process paradoxically results in an increase in the number of page faults. It occurs in FIFO page replacement, but cannot occur in stack-based algorithms like LRU or Optimal.

Q5: What are Coffman's four conditions for deadlock?

Mutual Exclusion, Hold and Wait, No Preemption, and Circular Wait. Deadlock can arise if and only if all four conditions hold simultaneously.

Q6: How does Copy-On-Write (COW) optimize fork()?

During fork(), instead of duplicating physical RAM pages, the kernel shares pages between parent and child marked as read-only. When either process attempts to write, a page fault triggers the OS to duplicate that single page in RAM, saving immense CPU time and memory.

Q7: What is Thrashing and how can the OS resolve it?

Thrashing occurs when a process spends more time paging data between RAM and swap disk than executing instructions, collapsing CPU utilization. It is resolved using the Working Set Model by ensuring processes receive their complete working set of frames, or by suspending processes to reduce multiprogramming degree.

Q8: Differentiate between Internal and External Fragmentation.

Internal fragmentation occurs when allocated memory blocks exceed the memory requested by the process, wasting space inside the partition (common in Fixed Partitioning and Paging). External fragmentation occurs when total free memory is adequate but broken into non-contiguous scattered holes (common in Variable Partitioning and Segmentation).

Q9: What is a Spinlock and when is it preferred over a Mutex?

A spinlock busy-waits in a loop on the CPU until the lock becomes free. It is preferred over a Mutex on multicore systems when the critical section is extremely short, because the spinlock loop overhead is smaller than the costly kernel context switch required to put a thread to sleep and wake it back up.

Q10: What is the difference between Zombie and Orphan processes?

An Orphan process is running after its parent has terminated; it is adopted by PID 1 (systemd/init). A Zombie process has terminated via exit(), but its parent has not yet called wait(); it occupies a process table slot until harvested.
